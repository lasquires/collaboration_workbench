# Human journal-sharing review

Implement the existing backend review in a dedicated Sharing tab. The page shows safe proposed public details, source hash attribution and current choices. Original local note remains accessible through the task map. Every changed review requires explicit mode selection and a publication acknowledgment; choices are not automatically rebased. Current project/principal/role are read with the page. Twenty notes per snapshot page, explicit next-page control, and no silent truncation.

Use an isolated state controller in docs/workspace-sharing.js with load/choose/save/discard methods and safe textContent rendering. Freeze the exact transaction body/request ID on first save. Unknown/5xx/malformed-success responses retain that body and block navigation/discard; retry sends identical bytes. Confirmed4xx ends uncertainty;409 locks the old review until explicit fresh load. Successful save is confirmed by matching receipt then reloads the review separately. Late loads cannot paint another project. Existing dashboard draft guards remain authoritative and must not silently discard this controller state.

Tests cover no default choices, explicit acknowledgment, current shared review role, exact request replay, stale review, malformed acknowledgment, paging and project isolation. Browser QA uses a separate synthetic database/service, not the source authority: save and inspect raw original/portable disclosure, concurrent409, uncertain reply followed by exact replay, escaped source text, mobile layout. Add the new asset to the explicit service whitelist. No broader layout clone or source-project cutover in this slice.
