# Recover reviewed live commands

A successful join or conflict resolution can lose the local-service response. Existing durable network outbox protects remote retries, but replaying the outer reviewed command currently fails after completion. Derive a command digest from exact kind/review/choices; bind it to the current authenticated host principal and installation. Persist it on the job before mutation. Exact pending replay resumes the same job; join/local completion records a small receipt atomically with clearing the outbox. A host-resolution receipt is recorded with the confirmed remote acknowledgment and transition to pull, so a later local conflict cannot erase it. Matching request ID, revision and changed-record envelope are required before accepting a remote200. Exact completed replay returns current status plus an acknowledgment of that command (which does not claim the remaining data reconciliation is complete), after rechecking current host access. Changed choices remain a different command and cannot replace an in-flight write or silently rebase.

Keep the most recent256 reviewed-command receipts in ordered private client state; never portable data. Older replay cannot recreate a completed join or an expired resolution because the existing base/job guards remain. Job receipt validation is strict and bounded. Background synchronization may finish a prepared reviewed command but cannot prepare a new reviewed choice or a lease action. A crash after SQLite commit but before client-state save replays the original stored transaction request ID.

Tests fail-before then pass for completed join across restart, host/local resolution across restart, pending remote lost reply, local commit/state-save failure, changed choices, actor/store mismatch, revoked credentials and receipt corruption. Real authenticated HTTP confirmation and independent review precede publication. Live UI integration and source authority cutover remain required separate gates.
